## Cursor Troubleshooting — 2025-08-19

### Issues covered
- **Cmd+C not working in Cursor**
- **Chat not responding/unresponsive**

### Cmd+C not working in Cursor
- **Verify keybindings**
  - Open Keyboard Shortcuts (Cmd+K, then Cmd+S) → search “Copy”. Ensure “Copy” is bound to Cmd+C and there are no conflicting bindings in the same `when` context (e.g., `editorTextFocus`).
  - Click the three dots in Keyboard Shortcuts → “Reset Keybindings” if conflicts persist.
  - Command Palette (Cmd+Shift+P) → “Preferences: Open Keyboard Shortcuts (JSON)” → remove any custom Cmd+C overrides.

- **Disable extensions that intercept keys**
  - Temporarily disable Vim/keymap/AI/clipboard-related extensions. Users reported Codiumate and similar tools can block copy in some setups.
  - Test with extensions disabled (Safe Mode):

```bash
/Applications/Cursor.app/Contents/MacOS/Cursor --disable-extensions
```

- **Check macOS app-specific shortcuts**
  - System Settings → Keyboard → Keyboard Shortcuts → App Shortcuts → remove overrides targeting Cursor.

- **Permissions**
  - System Settings → Privacy & Security → Accessibility and Input Monitoring → allow Cursor if present.

- **Note**
  - Custom multi-key bindings (e.g., Cmd+C+L) have been known to shadow copy; removing the custom binding restored Cmd+C for some users.

### Chat not responding
- **Quick checks**
  - Help → “Reload Window”.
  - Sign out of Cursor and sign back in.
  - Temporarily disable all extensions and retest.

- **Inspect errors**
  - Help → “Toggle Developer Tools” → Console: look for network/auth errors.
  - View → Output → select “Cursor”/“AI” channels and review logs for failures.

- **Network/session**
  - Disable VPN/proxy/firewall to test; try a different network.
  - Known trigger: pasting screenshots then deleting them in a chat can stall the thread; remove orphaned attachments in the conversation if visible.

- **Network diagnostics**
  - Settings → Network → "Run Diagnostics" to test connection to Cursor servers.
  - Force HTTP/1.1 fallback (for corporate/VPN networks):
    - Settings (Cmd+,) → search "HTTP/2" → enable "Disable HTTP/2".
  - Allowlist domains in firewall/proxy:
    - `*.cursorapi.com`
    - `*.cursor.sh`
    - `marketplace.cursorapi.com`

- **Extension conflicts**
  - Disable AI extensions temporarily (Continue, Copilot, etc.) and reload.
  - Check for extension errors in DevTools Console that may destabilize the extension host.
  - Known issue: Continue extension can cause LanceDB errors; update or disable if not needed.

d- **Cache cleanup (non-destructive)**
  - Quit Cursor, then remove cache folders:
```bash
rm -rf "$HOME/Library/Application Support/Cursor/Cache"
rm -rf "$HOME/Library/Application Support/Cursor/Code Cache"
rm -rf "$HOME/Library/Application Support/Cursor/GPUCache"
```

- **Reinstall (non-destructive)**
  - Download the latest Cursor, reinstall, and keep user settings. Test before re-enabling extensions.

- **Reset local state (destructive; backs up first)**
  - This clears chats, extensions, keybindings, etc. Back up and reset:

```bash
# Backup
mkdir -p "$HOME/Desktop/cursor-backup-$(date +%Y%m%d_%H%M%S)"
mv "$HOME/Library/Application Support/Cursor" "$HOME/Desktop/cursor-backup-$(date +%Y%m%d_%H%M%S)/" 2>/dev/null || true
mv "$HOME/.cursor" "$HOME/Desktop/cursor-backup-$(date +%Y%m%d_%H%M%S)/" 2>/dev/null || true

# Reset (irreversible if run without the backup step)
rm -rf "$HOME/Library/Application Support/Cursor/"
rm -rf "$HOME/.cursor"
```

### Useful references
- Keybinding conflicts and resets have resolved Cmd+C issues for multiple users (e.g., removing custom sidebar or multi-key shortcuts).
- Extensions (e.g., Codiumate) have been reported to interfere with Cmd+C and chat behavior; testing with extensions disabled isolates this quickly.

### Minimal checklist (fast path)
1) Reset/verify “Copy” keybinding → 2) Launch with `--disable-extensions` → 3) Reload Window and sign out/in → 4) Check DevTools Console/Output logs → 5) Reinstall → 6) Optional: reset local state (with backup).
